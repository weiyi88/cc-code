# agent-whole-qa — 全量验收 + 修复闭环编排器

> **与 `qa` agent 的关系**：`qa` 是「单模块测一次」的原子能力；本 skill 是「全模块 × 多轮 + 修复回环」的编排层，**复用 `qa`，不重写测试逻辑**。
> **与 `agent-mvp` 的关系**：`agent-mvp` 每阶段用 `qa` 做增量验收；本 skill 用于 **MVP 收口前的一次性全量清算**。
> **主控是编排者，不扮演任何角色**：派哪个 agent 就是哪个角色（权限唯一出处 = `active/Agent.md` §三）。主控的写权限见 `active/Agent.md` §一；清点与汇总记账、`gates.md`、`docs/qa/**`、视觉测试与截图基线全归 qa，修复归 dev。

## ⛔ 六条硬约束（违反任一即本次验收无效）

### 1. 你是编排器，不是执行者
```
❌ 错：agent-whole-qa 自己测、自己修
        → 测的人知道修的人怎么想，修的人知道测的人怎么测 → 互相糊弄
✅ 对：agent-whole-qa 只做 清点 / 分发 / 汇总 / 循环控制

    agent-whole-qa（不碰代码，不碰需求，不碰验收记录）
       ├─ Agent(subagent_type=qa)  ──► 清点 / 测 / 汇总记账（测的时候只拿到断言，不知道谁会修）
       └─ Agent(subagent_type=dev) ──► 修（只拿到 FAIL 清单，不知道怎么测的）
```
主控**绝不**自己写测试、自己改代码。发现自己在写 `expect(...)` 或改 `src/` 就是越界了。

### 2. 分母先锁定，再开测
INVENTORY 阶段的产物落盘后**本轮分母不可变更**。禁止中途以「这个按钮不用测」「这个接口是内部的」为由缩小分母。要改分母，只能作废本轮重新开始。

```
全量分母固定为五个基础分母 + 一个视觉组合子行：
  断言 A / 页面五态 U / 可交互元素 E / 接口 / 视觉 V 行
  └─ 视觉组合子行 = V 行 × 视口集合 × 亮暗        ← 只记组合覆盖，⛔ 不乘进 V 行分母

  视觉分母口径（唯一出处 = skills/cc-code/references/ui-gates.md §8.2）
    全量轮：V0.02 全站 + 每页每适用组 + 全站性能 V0.09
    V0.01（设计数值）只在锁定前复核出，全量轮不出
    ⛔ V 行不按「视口 × 亮暗」乘开；屏宽与亮暗写证据列
```

### 3. 禁止修需求，也禁止动尺子
```
本 skill 及其派生的 dev subagent 对以下文件【只读，绝对禁写】：
    active/prd.md      active/ux.md      active/api.md
    active/design.md   ← 视觉数值（V 段判词的尺子）
    .cc_code/test/visual/**          ← 视觉测试与基线（qa 独占写）
    .cc_code/test/visual/baseline/** ← 截图基线与允许值集合
修不动 → 标记 ESCALATE 交人决策
```
> 这是 AI 修 bug 时最常走的偷懒路径：改断言 / 改基线让测试变绿。不用规则堵死，它一定会走。⛔ 主控不代写 `design.md`、不代为更新基线。

### 4. 收敛门控
```
第 N 轮 FAIL 数 必须 < 第 N-1 轮 FAIL 数
  ├─ 不递减        → 停止，报告「未收敛」，交人决策
  ├─ 出现新增 FAIL → 停止（修 A 坏 B），报告震荡点，建议回滚本轮
  └─ 最多 3 轮
```

### 5. 回归门（每轮必跑）
```
每轮修完，重跑范围 = 本轮 FAIL 项  +  affected 算出的真实影响面
                                    ↑ 缺这半段就会「越修越坏」而毫不知情

  ⭐0.10.0：影响面从「同模块已 PASS 项」升级为 codegraph affected 算出的
  传递闭包 —— 同模块是人凭直觉画的圈，affected 是沿 import 图算出的事实，
  跨模块的隐式依赖只有后者抓得到。

  codegraph affected <本轮修改的源文件...>
    非 .spec/.test 命名的测试补跑 --filter "<project.md §六 登记的 glob>"
    返回空 → 报一行「未匹配到测试，本轮用全量」+ 自查三点：
             ① 测试代码是否被 .gitignore 屏蔽（被 ignore 则不进索引）
             ② 测试是否 import 被测源码（纯 HTTP 型无 import 边，追不到）
             ③ 命名是否需 --filter
    CLI 未装 → 静默退回「同模块已 PASS 项」，不报
```

**视觉回归的追加规则**（阈值与基线纪律唯一出处 = `skills/cc-code/references/ui-gates.md` §五、§七）：

```
视觉项重跑 ──► 只比 project.md §六 登记的基线目录，按登记容差判
              整页像素差 >1% / 组件局部 >0.5% → 判回归（本项 FAIL）
              颜色每通道 ±2；圆角 / 阴影 / 间距 ±0.5px；字号 ±0.5px

失败轮 ──► ⛔ 禁止冻结基线、⛔ 禁止更新基线、⛔ 禁止改阈值
           本轮范围内的新页 / 改版页差异 → 只列候选，标「主人未目视」
           本轮范围外的差异 → 判回归，⛔ 不得当成「顺手更新基线」

未冻结基线 / 无基线的新页 ──► VH-09.07 标 UNVERIFIABLE、不进分母；只列候选
```

### 6. 禁止静默截断
未测的元素/接口/断言，必须逐条列入 `SKIPPED` 并给原因。同构重复元素若做了组内抽样，必须写明「同构组 N 个，实测 M 个」—— **报告里出现「全部覆盖」而分母被悄悄缩小，是最严重的失职**。视觉组的未测项同样逐条列原因（组不适用不等于不用记）。

## 👁 视觉判定的唯一口径（第四层）

```
 视觉层（第四层）判词怎么来
   ├─ 机器检查 ── Playwright 测试 / axe / 截图比对 / Lighthouse 命令行
   │     └─► VH（阻断）/ VM（次要）──► gates.md §2.4 V 段 ──► 唯一判词来源
   ├─ 视觉模型看图（qa 的多模态能力）──► 只作 VS 线索 ──► 合集板
   │     └─► ⛔ 不写 VH / VM、⛔ 不阻断、⛔ 不进分母
   └─ 无基线 / 无门命令 / 无驱动工具 ──► 标 UNVERIFIABLE，交人，⛔ 不静默通过
```
> 规则号（`VH` / `VM` / `VS`）、组码、阈值、允许值集合、基线纪律的唯一出处 = `skills/cc-code/references/ui-gates.md`；本 skill 只编排，⛔ 不复述规则内容。

## ⚙ Workflow 编排模式（Claude Code 默认；工具不可用时自动回退）

本 skill 的 ❶ 清点 → ❷ fan-out → ❸ 汇总 → ❹ 修复回环，在 Claude Code 端交给 Workflow 引擎执行；主控只做 ⓿ PREFLIGHT、启动应用、传参、❺ 收口写回。规则出处不变：本 skill + `parallel-lanes.md` + `Agent.md`，脚本只是机械执行器。

```
 主控 ⓿ PREFLIGHT + 后台启动应用（不开浏览器）
          ▼
 读 references/whole-qa.workflow.js
          ▼
 调用 Workflow（后台）──► 清点(owner 开唯一浏览器) → 按模块 fan-out → 视觉层(全部页面×视口×亮暗) → 汇总(五基础分母) → 修复回环（≤3 轮）→ 收口(冻候选基线 + 合集板，closer 关)
          ▼                              │
     完成通知 ◄────────────────── 终态（pass / escalate / aborted）
          ▼
 主控 ❺ 收口：milestone-log + status.md + 向主人报告
```

**启动方式**：应用就绪后，优先 `Workflow({ scriptPath: "<本 skill 目录>/references/whole-qa.workflow.js", args })`；宿主不认路径时，Read 全文后用 `script` 传入。浏览器实例由**清点 qa（owner）**打开、**收口 qa（closer）**关闭；主控的 `allowed-tools` 不含浏览器工具，⛔ 不代开代关。

**args**

| 键 | 值 |
| --- | --- |
| `projectRoot` | 生成项目的 `.cc_code` 路径 |
| `baseUrl` | ⓿ 启动后的应用地址 |
| `date` | 今天的日期（脚本内取不到时间，必须由主控传） |
| `concurrency` | 并发上限，读 `project.md` §九，缺省 3 |
| `maxRounds` | 缺省 3 |
| `qaAgentType` / `devAgentType` | 与 Agent 工具可用名称一致（如 `qa` / `dev`；宿主带命名空间时传带前缀的） |
| `browserTool` | 浏览器工具逻辑名，`project.md` §六 有登记就用登记值，否则从宿主可用工具前缀自动识别（如 playwright / chrome-devtools）；全流程单实例复用，规则见 `parallel-lanes.md` §九 |
| `designSpec` | 视觉数值唯一事实源，缺省 `<projectRoot>/active/design.md` |
| `baselineDir` | 截图基线与允许值集合目录，取 `project.md` §六 登记值（缺省 `.cc_code/test/visual/baseline/`）；脚本只传路径，⛔ 不判断基线内容 |
| `viewports` | 视口集合，取 `project.md` §六 登记值（缺省 `[390, 1440]`；`768` 只在 `ux.md` 声明时加入） |
| `colorModes` | 亮暗模式，取 `project.md` §六 登记值与 `ux.md` §1.1「明暗」列（缺省 `["light"]`） |

**铁律**

- 脚本只做机械调度；角色权限、测试口径、写者归属只来自本 skill 与 `Agent.md` / `parallel-lanes.md`，⛔ 不在脚本里另写一份规则。
- 运行中不能问人：ESCALATE / 冲突一律作为返回值带回，由主控交人。
- 不静默缩分母：脚本返回的 `skipped` 必须逐条报给主人，视觉组的未测项同样逐条。
- 视觉判词只认机器检查；视觉模型输出只能进 VS 线索与合集板，⛔ 不进 `failures`、⛔ 不阻断。
- 轮次中 ⛔ 冻结 / 更新基线、⛔ 改 `design.md`、⛔ 改阈值；只有收口 qa 才能在「本轮范围」内冻候选基线。
- Workflow 工具不可用（如 Codex 端）→ 按本 skill 下文原有的 Agent 多开流程执行，零改动；回退时下面几条逐条对齐，⛔ 不得只在 Workflow 分支里做视觉：

| 回退到 Agent 多开流程时 | 必须与 Workflow 分支同口径 |
| --- | --- |
| ⓿ 前置检查 | 同视觉门、陈列页未上线、`project.md` §六 视觉基建必备登记 |
| ❶ 清点 | 同六维分母与视觉 `V[]` 清点，落盘即锁 |
| ❷ 并发 | 模块 qa 同时完成逻辑三层与视觉 V 段机检 |
| ❸ 汇总 | 同五基础分母 + 视觉组合子行；VS 只进合集板 |
| ❹ 修复 | 同只读清单与「失败轮冻结禁止」 |
| ❺ 收口 | 同候选基线冻结 + 合集板，再由 closer 关浏览器 |

## ❷ FAN-OUT 分模块并发

每模块一个 `qa` subagent。**在单条消息里发出多个 Agent 调用**以并发执行。

> 🌐 **浏览器照常测，实例只有一个**：所有并发 qa 共用同一个浏览器实例，各自建 tab；
> **清点 qa 是 owner**（没有实例就建立，有就复用），**收口 qa 是 closer**（统一关一次）；
> 其他 qa 开工建 tab、每次浏览器调用前切回自己的 tab、收工只关自己的 tab，⛔ 不新开实例、⛔ 不关闭整个浏览器。
> 规则单一出处：`references/parallel-lanes.md` §九（此处不复述细节）。
