# INVENTORY 清点规则

> 被 `agent-whole-qa` 的 ❶ 阶段引用。目标：产出**可锁定、可追溯、可证明**的分母。
> **六个清点维度**：页面 / 可交互元素 / 接口 / 验收断言 / 页面五态 / 视觉 V 行；外加**视觉组合子行**（V 行 × 视口 × 亮暗，只记覆盖、⛔ 不乘进 V 主行）。
> **覆盖率口径的五个基础分母** = 断言 `A` / 页面五态 `U` / 可交互元素 `E` / 接口 / 视觉 `V` 行（页面是范围，不进覆盖率分母）。冗余检测不是分母，单列。
> 视觉规则号、组码、阈值、基线纪律的唯一出处 = `skills/cc-code/references/ui-gates.md`；本文件只讲**怎么清点**，⛔ 不复述规则。

## 一、页面发现 `P[]`

### 1.1 按框架扫路由

| 框架 | 扫描位置 | 路由规则 |
| --- | --- | --- |
| Next.js App Router | `app/**/page.{tsx,jsx,ts,js}` | 目录路径即路由；`(group)` 不入路径；`[param]` 为动态 |
| Next.js Pages Router | `pages/**/*.{tsx,jsx}` | 文件路径即路由；`_app`/`_document`/`api` 排除 |
| React Router | 搜 `createBrowserRouter` / `<Route` | 从配置对象提取 `path` |
| Vue Router | `router/index.*` 的 `routes` | 同上 |
| Nuxt | `pages/**` | 同 Next Pages |
| SvelteKit | `src/routes/**/+page.svelte` | 目录即路由 |
| 服务端模板（Django/Rails/Laravel） | `urls.py` / `routes.rb` / `routes/web.php` | 从路由表提取 |

> 拿不准框架时，读 `project.md` 的技术栈段；仍不确定则在报告里写「框架未识别」，交回主控由主控交人，**不猜**（你是 subagent，不能问用户）。

### 1.2 动态路由处理

```
/user/[id]        → 必须准备真实样本 id（从 seed 数据取）
/post/[...slug]   → 准备 1 段 / 多段 两种样本
```
无样本可用的动态路由 → 标 `SKIPPED(缺样本数据)`，并在报告中列出。

### 1.3 准入分层

同一页面在不同身份下是**不同的测试对象**：

| 身份 | 必测 |
| --- | --- |
| 未登录 | 受保护页应正确重定向 |
| 普通用户 | 正常功能 + 越权入口应不可见/不可用 |
| 管理员/特殊角色 | 特权功能 |

`ux.md` 标注了准入的页面，按其身份列表逐一进入。

### 1.4 组件陈列页单列

组件陈列页是项目内的不上线路由（`project.md` §九 视觉地基产出），清点时**单独成组**：

```
组件陈列页
  ├─ 不进生产页面分母、不进模块归属（单列「陈列页」组）
  ├─ 但它承载视觉 V0.03~V0.09 的页面行（视觉地基与全量都要测）
  └─ 清点必须记三项：路由 · 是否已上线 · 基线有无
       已上线 → 中止并交人（陈列页不得进生产）
       基线有 → 可判 VH-09.07 回归
       基线无 → 首轮「建基线」，本轮只列候选、不判回归
```

### 1.5 页面清点要带的字段

每页至少记：路由 · 端 · 形态 · 准入身份 · 动态参数样本 · 声明视口（来自 `project.md` §六 视口集合）· 亮暗 · 是否陈列页。

## 二、元素清点 `E[]`

### 2.1 ⭐ 从运行时 DOM 拿，不读源码

```
理由三条：
① 穷尽性  —— 条件渲染、动态插入的元素，读源码看不全
② 黑盒性  —— 不读实现，需求判断不会被代码带偏
③ 权限   —— 绕开「QA 禁读无关业务代码」的边界
```

流程：**清点 qa 是浏览器 owner** —— 实例不存在就建立、已存在就复用（⛔ 不新开第二个、⛔ 中途不关闭，协议见 `parallel-lanes.md` §九）→ 建自己的 tab → 导航到页面 → `snapshot` → 从可访问性树提取可交互节点 → 收工只关自己的 tab（实例留给收口 qa 关闭）。

### 2.2 什么算「可交互元素」

| 类型 | 匹配 |
| --- | --- |
| button | `<button>`、`role="button"`、`<input type="button/submit/reset">` |
| link | `<a href>`、`role="link"` |
| input | `<input>` 各 type（text/email/password/number/date/checkbox/radio/file…） |
| select | `<select>`、`role="combobox"`、`role="listbox"` |
| textarea | `<textarea>` |
| form | `<form>`（整体提交行为单独算一项） |
| tab | `role="tab"` |
| modal 触发器 | 点击后出现 `role="dialog"` 的元素 |
| 可拖拽 | `draggable="true"`、拖拽库标记 |
| 其他可点击 | 带 `onClick` 的 `div`/`span`（有 `cursor:pointer` 或 `tabindex`） |

**排除**：纯展示文本、装饰图标、`disabled` 且业务上永久禁用的（但「当前禁用、条件满足后启用」的必须测两态）。

### 2.3 定位锚点优先级

```
① data-testid          ← 最稳，文案改了不影响
② role + accessible name
③ 可见文本
④ CSS 选择器            ← 最脆，仅兜底
```
若 `ux.md` 的「可交互元素清单」已给 testid，直接用；实际 DOM 没有该 testid → 记为 FAIL（规格与实现不一致），不要自己换选择器蒙过去。

### 2.4 同构组识别

判定为同构组的条件（全部满足）：
1. DOM 结构路径相同（同一列表/表格的重复行）
2. 同一 testid 前缀或同一 class 组合
3. 行为只随数据变化，不随位置变化

```
处理：
  同构组 N 个 ──► 实测 首 / 末 / 边界样本（如：唯一项、最后一项、超长文本项）
  报告写明：  「M3-删除按钮 同构组 N=137，实测 3（首/末/超长文本行）」
```
⛔ 唯一元素**不许**当同构组处理。拿不准是否同构 → 按唯一元素逐个点。

### 2.5 断点适用性（每个元素必标）

断点 / 视口集合唯一出处 = `project.md` §六（缺省 390 / 1440，768 选做）；`ux.md` 各页断点布局变化（`<页章号>.5`）只声明布局变化，不重复视口数值。

```
每个元素标它在哪些登记视口上「存在且可操作」：
  全断点        ── 每个视口都要测
  仅桌面 ≥1024  ── 只在该档视口测
  仅窄屏 <768   ── 只在移动档测
  指定视口      ── 按 project.md §六 的登记集合点名

在某视口不存在 → 记「N/A@<视口>」，⛔ 不进该视口的元素分母、⛔ 不算 SKIPPED
```
> 清点表必须带「断点适用」列；这是后续按视口算元素覆盖、以及区分「该有没有」的依据。

## 三、接口发现 `A[]`

三个来源取并集，**差集必须报告**：

| 来源 | 方法 |
| --- | --- |
| ① 代码路由 | Next.js `app/api/**/route.ts` / `pages/api/**`；Express `app.{get,post,...}`；Django `urls.py`；等 |
| ② 契约表 | `api.md` 的接口清单 |
| ③ 运行时 | 页面操作过程中浏览器实际发出的请求（`list_network_requests`） |

```
差集含义：
  ②有 ①无  → 契约已定但未实现          → FAIL（No implementation found）
  ①有 ②无  → 影子接口，契约未登记        → FAIL（契约缺失，Architect 需补）
  ③有 ①②无 → 外部服务或未纳管路由        → 列入报告，标 EXTERNAL
```

每个接口的 5 类断言见 `skills/cc-code/references/assertions.md`（全部 qa 命令共用的断言库）。

## 五、视觉清点 `V[]`

> 视觉层（第四层）的分母清点。规则号、组码、适用组、分母口径的唯一出处 = `skills/cc-code/references/ui-gates.md`（§三 9 组总表、§8.2 行号与分母、§十 形态规则包）；本文件只写清点时要采集哪些事实。

### 5.1 来源四处（取并集，缺一必须报告）

| # | 来源 | 取什么 | 缺了怎么办 |
| :-- | :--- | :--- | :--- |
| ① | `ux.md` §一（1.1 前端形态表 + 1.2 页面清单） | 每端形态、覆盖页面、主设备与最小宽度、明暗、界面语言 | 缺形态表 → 交人（无法定适用组，⛔ 不猜） |
| ② | `design.md`（§0 状态、§二~§八 数值、附录 B 例外） | 是否已锁定、数值与例外范围（用来定组与允许值来源） | 状态非「已锁定」且有前端 → 前置检查已中止 |
| ③ | `ui-gates.md`（§三 组表、§8.2 分母口径、§十 形态规则包） | 本端形态适用哪些组、哪些组不适用 / 推迟、V 行口径 | 找不到适用包 → 按 §十 对应形态行处理，仍无则交人 |
| ④ | `project.md` §六 + 基线目录实际文件 | 视觉门命令、视觉测试位置、基线目录、视口集合、亮暗模式、性能门限、冒烟页；每页基线有无 | 任一项缺 → 交人（前置检查挡住） |

### 5.2 V 行的生成口径

```
本轮是全量验收（开发后 + 性能）
  V0.01  锁定前专用（design.md 已在前置检查确认锁定）→ 本轮不出行
  V0.02  全站依赖与源码：按端各查，汇总成一行
  V<页章号>.03 ~ .08   每个业务页 × 每个适用组一行；组不适用 → 不出行
  V<页章号>.09         每个业务页一行（响应式 / 可访问性 / 基线）
  V0.09                全站性能一行（Lighthouse 命令行）

视觉地基轮次（无业务页）→ 03~08 与 09 的页面行全部落在 V0.xx（组件陈列页）
```

- **页章号**取 `ux.md` 的页面章号（第一个页面章为 `2`），`0` = 全站级；新页只追加，⛔ 不在中间插页。
- **一行 = 一个页面（或全站）× 一个适用组**；屏宽与亮暗写**证据列**，⛔ 不乘成行。
- **规则号原样引用**（如 `VH-06.01`），⛔ 不另起编号；**V 行号**（如 `V2.06`）与规则号是两套，⛔ 不混。
- **VS 人判不进本表、不进分母**：清点不列 VS 行，它在测试后由 qa 整理进合集板。

### 5.3 基线有无（每行必标）

| 取值 | 含义 | 本轮怎么判 |
| :--- | :--- | :--- |
| **有** | 基线目录里找到同「端 × 视口 × 亮暗 × 浏览器 × 系统」文件 | 按 `ui-gates.md` §五 容差判 `VH-09.07` |
| **无** | 新页 / 从未冻结 | 本轮只列候选，标 `UNVERIFIABLE`、不进分母；⛔ 失败轮不冻结 |
| **首轮** | 基线目录为空 | 本轮全部视觉项只建候选基线；其余组照查 |
| **不适用** | 该规则不查此形态 / 小程序推迟 / 原生 App 无法判定 | 不出行；覆盖率备注写清原因 |

### 5.4 不适用与推迟

```
无前端（design.md = 不适用（无前端））→ 视觉段整段不适用，V[] 为空
跨端编译小程序 / 原生小程序        → 视觉规则包第一版推迟，只记驱动工具契约位
跨平台原生 App                     → 视觉段标「无法判定」，不进分母
不适用组                           → 不出行，覆盖率备注「组不适用」
```

## 六、模块归组 `M[]`

以 `prd.md` 的「模块清单」为准。把 `P[]`/`E[]`/`A[]` 归属到模块：

```
归属规则：
  页面 → 按 ux.md 的页面-模块对应，或按路由前缀
  元素 → 跟随所在页面
  接口 → 按 api.md 的「模块：xxx」分段
  视觉 V 行 → 跟随所在页面；全站级 V0.02 / V0.09 单列「全站」组，不归模块
  
孤儿项（归不进任何模块）→ 单列「M0 未归属」组，照测，
                          并在报告中提示主人：模块归属缺失，走 plan-feature 由 pm 补 prd.md
```

## 七、冗余检测 `DEAD[] / ORPHAN[] / DUP[]`

> 测「不该有的有没有」—— vibecoding 多次修改易留死代码/孤儿文件/重复实现。
> agent-whole-qa 本来就全量扫代码，顺带做，零额外负担。用 codegraph 查（亚毫秒，不读文件）。

### 1. 死代码 `DEAD[]`
codegraph 扫所有 export（函数/类/常量/组件），`callers` 为空且不在路由/入口被引用 → DEAD。
排除：入口文件本身（`page`/`route`/`main`）、类型导出、barrel `index.ts` re-export。

### 2. 孤儿文件 `ORPHAN[]`
codegraph 扫所有源文件，无任何 import 引用它 → ORPHAN。
排除：入口文件、配置文件、测试文件、`.d.ts`。

### 3. 重复实现 `DUP[]`（半自动，人审）
codegraph 按行为聚类：同名 / 签名相似 / 调用同一组依赖 → 列候选对，人工确认是否真重复。

### 4. 过度抽象 `OVER_ABSTRACT[]`（人工）
提示 Architect 审查：单层无调用方的 wrapper / facade；为「未来扩展」预留但当前无用的接口/参数；单实现却抽象出 interface（YAGNI）。

### 判定
| 类型 | verdict | 处理 |
| --- | --- | --- |
| DEAD / ORPHAN | ⚠️ 应清理 | 列清单交 Dev，不阻塞 Verdict |
| DUP | ⚠️ 人审 | 候选对，人工决定合并 |
| OVER_ABSTRACT | 💡 建议 | 提示 Architect，不强制 |

> 冗余项**不算 FAIL**（功能没问题），但必须在报告列出 —— 否则项目越来越臃肿，违背防治「多次修改冗余」的初衷。
