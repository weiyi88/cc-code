> **受众**：`uiux`（锁定前自检）、`dev`（实现时避开）、`qa`（执行验收）。architect 只按本文的检查时机名与产物路径填 `.cc_code/active/project.md` §六，不读 `design.md`，不另立视觉阈值。
> **一句话**：把「高级感、去 AI 味、视觉对齐」落成可机检的规则与阈值。本库是 **qa 视觉层（第四层）的唯一尺子**；**全仓的视觉规则、编号、判词只在本文件写一次**，其他 skill / agent / 模板只留指针，⛔ 不复述。

## 二、三级判词

| 判词 | 前缀 | 含义 | 阻断 | 进分母 | 触发回环 | 去向 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **阻断** | `VH` | 明确违反可机检的硬阈值 | 是 | 是 | 是（≤3 轮，机制见 `dev-qa-loop.md`） | `gates.md` §2.4 V 段 → §三 Critical Failures → 回 dev |
| **次要** | `VM` | 可修的质量问题，不构成不合格 | 否 | 是（随所属组行） | 否 | `gates.md` §2.4 行内 → §四 Minor Failures |
| **人判** | `VS` | 只能靠人看截图判断的审美与格调问题 | 否 | 否 | 否 | **合集板**（`.cc_code/docs/qa/`），主人看 |

**判词纪律**：

1. **一条 VH 命中 → 所在页的所在组行判 FAIL**；同组其他 VH 也一并列出。只有 VM 命中时，该行判 PASS，但必须在实测结果列写清 VM 编号与数值，并同步进 §四。
2. **VS 永不改 V 段行的判词、永不进分母、永不触发回环**；只以截图 + 一句观察进合集板。
3. **视觉模型（含任何图像理解模型）只给证据，不给判词**：它的输出只能作为 VS 的线索写进合集板，⛔ 不得据此写 VH / VM，更不得阻断。
4. **同一事实只判一次**：逻辑层已由 `assertions.md` 覆盖的项目（如页面出现 `undefined` / `NaN`），视觉段不再另立编号（见 VH-07.02 注）。
5. **先机检、后目视**：先跑 VH / VM，再整理 VS；⛔ 不得因为「看起来不错」跳过机检，也不得因为 VS 观感差而补一条 VH。
6. **无法判定**：证据不足时（锚点未登记、基线未冻结、非 100% 缩放等）标 `UNVERIFIABLE`（沿用 `gates.md` 既有取值）；不算 PASS、不进分母、交回补证据。

## 三、三个检查时机

```
  现有产品（尚未锁风格）              design.md 草稿 + 风格样板板                 项目代码（视觉地基之后）
          │                                    │                                        │
  ① 现状体检（qa，plan-uiux 模式二）    ② 锁定前 · 自检（uiux，plan-uiux）      ③ 开发后（qa，各执行命令）
          │                                    │                                        │
   现有页面截图 + 机检                    design.md + 样板板全组自检              本次受影响页面 × 视口 × 亮暗 × 五态
          │                                    │                                        │
          ▼                                    ▼                                        ▼
   问题清单 → uiux 当输入              主人「定了」→ design.md 锁定             V 段行 + 合集板 → 回 dev / 收口
                                               │
                                               ▼
                                     agent-mvp 视觉地基（dev 搭主题）
                                               │
                                               ▼
                                     ②′ 锁定前 · 复核（qa）──► 首次冻结截图基线
                                               │
                                               └──────────────────────────────────────► ③
          └──────────── 改版时回到 ①（plan-uiux 模式二）──────────────────────────────────┘
```

> ①②③ 只是时序编号；时机名一律写「现状体检 / 锁定前 / 开发后」，⛔ 不自造别名。

| 时机 | 触发命令 | 谁查 | 查什么对象 | 查哪些组 | 产出与去向 | 写 `gates.md` |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **现状体检** | `plan-uiux` 模式二 | qa | 现有产品页面（截图 + 运行时） | 02、05~09；03 / 04 只做一致性观察（无 `design.md`，不作允许值判定） | 体检报告 + 现状截图 → `.cc_code/docs/qa/`，原样交 uiux 当目标输入 | 否 |
| **锁定前 · 自检** | `plan-uiux` 模式一 / 模式二 | uiux | `design.md` + 风格样板板（含样板板截图） | 01~08 + 09 的响应式 / 可访问性（性能与基线不在本时机） | 自检结果写进 `design.md` 锁定记录与设计报告 | 否 |
| **锁定前 · 复核** | `agent-mvp` 视觉地基阶段 | qa | 主题入口 + 全局框架 + 组件陈列页（项目内不上线路由） | 01~09（性能除外；基线在此首次冻结） | `gates.md` V0 行 + 基线 | 是 |

> **判词从哪开始**：现状体检只做诊断（按规则号归类问题，不出 PASS / FAIL、不进 `gates.md`）；锁定前·自检是 uiux 的内部放行条件，也不是验收判词。**真正的视觉判词从「锁定前·复核」开始**，由 qa 写 V 段。

### 规则表的读法

- **规则号**：`VH-<组码>.<序>` / `VM-<组码>.<序>` / `VS-<组码>.<序>`；组码两位、序号两位。⛔ 不使用 G / S 等断言库前缀。
- **适用形态缩写**：`全` = 全部有前端形态；`网` = 网页四形态（营销 / SaaS / 后台 / 文档）；`营销` = 营销落地页；`SaaS` = SaaS / Web App；`后台` = B 端中后台；`文档` = 内容与文档门户；`H5` = 移动 H5 营销微站（混合 App 按 H5）；`中文` = 中文界面。
- **检测方式只用七种**：设计数值解析 / 依赖与源码扫描 / 运行时样式与几何 / axe / 截图比对 / 性能采样 / 人判。
- **「适用形态」为空的规则**表示全形态；写 `N/A` 的形态不进入分母，也不出 V 行。

## 五、允许值集合与容差

### 5.1 集合定义

| 符号 | 是什么 | 什么时候采集 | 谁采 |
| :--- | :--- | :--- | :--- |
| `D` | `design.md` §二 色彩、§三 字体与排版、§四 间距与栅格、§五 形状与深度、§八 组件长相里声明的数值（按 `design.md` 的机器可读导出口径解析） | 锁定 / 改版定稿时 | qa 从 `design.md` 解析 |
| `G` | 已批**组件陈列页**实际渲染的取值快照；自动包含组件库派生的悬停 / 按下 / 焦点色 | 视觉地基过门时快照 | qa |
| `A` | token 生成的透明度变体：同一基色的任意 alpha 值，但必须来自主题变量，⛔ 不是任意字面量 | 与 `D` / `G` 同步 | qa |

- **允许值集合 = D ∪ G ∪ A**。
- **只采样静止态**；交互态（悬停 / 按下 / 焦点）不采样，但其派生色必须在集合内，避免未来出现时误报。
- **排除**图片、SVG、画布、iframe 内部。
- **单位统一换算为 px**（rem / em 按根字号换算后再比）。
- **集合刷新**：只在锁定、主人说「定了」后的改版定稿、或 `agent-uiux` 收口时重算；⛔ 不因某次实现「差不多」而临时扩充。

## 六、视觉对齐的测量口径

> 本节只讲**怎么量**；规则与阈值在 §4.6，⛔ 不在这里另立规则。

| 项 | 口径 |
| :--- | :--- |
| **取盒** | 取元素未取整的渲染盒（含边框、不含 transform 后的视觉偏移）；对比时允许亚像素抗锯齿差异，差值 >1px 才算不齐 |
| **行内对齐** | 同一 flex / grid 行内的元素，比较垂直中心线；图标 + 文字混合时以文字视觉中线为准 |
| **边缘对齐** | 同组元素的左 / 右 / 顶 / 底边缘两两比较；卡片组比顶部与底部，字段组比左边缘 |
| **基线** | 不同字号混排（如大标题 + 小标签）比文字基线，不比盒顶 |
| **间距** | 同一组重复项的相邻 gap / margin 实际渲染值；与 `design.md` §四 间距阶梯比对 |
| **栅格** | 列数与槽宽取 `design.md` §四；主内容区块左边缘应落在列线，独立左边缘位置数取「栅格列数」与 5 的较小值作上限 |
| **数字列** | 表格 / 统计 / 金额列右边缘；同时检查是否启用等宽数字 |
| **排除** | 装饰性元素、旋转 / 倾斜元素、粘性 / 固定浮层、刻意错位的签名单品（须在 `design.md` §四 登记） |
| **缩放** | 只在 100% 缩放、同一设备像素比下测；否则标 `UNVERIFIABLE`，不猜 |
| **光学修正** | 圆形图标、播放键等 1~2px 视觉补偿归 `VS-06.01` 人判，⛔ 不机检 |

| ② | 阶段 / 增量过门 | `agent-mvp` 后续阶段、`agent-feature` | 仅本阶段 / 本增量新增、且本身属于「组件陈列页 / 该形态样板必含页」的页面；新增业务页只落截图证据 | 视觉层 PASS；视觉地基基线不因推进而重冻，除非本次改动命中且被判回归 |
| ③ | 改版收口 | `agent-uiux` | 本次改版受影响、且原本已在基线范围内的页（重冻）；受影响业务页只落截图证据 | 视觉层 PASS |
| ④ | 视觉缺陷修复 PASS | `agent-debug` | 只重冻「受影响且原本已有基线」的页 | B-n 条目闭环 PASS |
| ⑤ | 全量验收收口 | `agent-whole-qa` | 本轮范围内尚未冻结的组件陈列页 / 样板页，生成候选（`-candidate`，标主人未目视） | 收口时；候选由 qa 冻结，主人后续否决则回改并重冻 |

> ⛔ 超出上表的任何时点、任何页面都不得冻结或更新基线。各执行命令（`agent-mvp` / `agent-feature` / `agent-uiux` / `agent-debug` / `agent-whole-qa` / `plan-debug`）只写「本命令在何时触发本 §7.2」，⛔ 不自立冻结时点与范围；其原文与本表冲突时以本表为准。
> **重冻** = 用本次 PASS 的截图替换同一路径的既有基线（⛔ 不加 `-candidate`），并在报告记日期与原因；只允许上表 ③④，以及 ② 中命中既有样板页 / 陈列页的情形。

**通用纪律**

| 项 | 纪律 |
| :--- | :--- |
| **谁生成** | **只有 qa**。uiux 的样板板截图属设计产物（`.cc_code/design/`），不是基线；dev ⛔ 不碰基线 |
| **失败轮** | ⛔ 禁止冻结、禁止更新基线、禁止改阈值。先修实现，再谈基线 |
| **比对范围** | 只比上条「基线范围」里的页面；其他页面用截图作证据与合集板素材，⛔ 不做像素比对 |
| **范围内差异** | 本次改动范围内的页面差异超阈值 → **生成新候选**，文件名加 `-candidate`，在 `gates.md` 与合集板标「主人未目视」。候选可按上表 ⑤ 在收口冻结，主人后续否决则回改并重冻 |
| **范围外差异** | 判**回归**，按 `VH-09.07` FAIL 回 dev；⛔ 不得当成「顺手更新基线」 |
| **平台分文件** | 按「浏览器 + 操作系统」各存一份，⛔ 不跨平台覆盖、不跨设备像素比比较 |
| **遮罩动态区** | 时间戳、计数、头像、随机图表、轮播、实时数据、广告、动画中间态一律遮罩；等字体加载完成再截 |
| **入 git** | 基线目录 `.cc_code/test/visual/baseline/` 必须入 git；⛔ 全局忽略截图；只允许忽略临时截图目录（以 `project.md` §六 登记为准） |
| **命名建议** | `<页章号>-<端>-<视口>-<亮暗>-<浏览器>-<系统>.png`；候选追加 `-candidate`。命名不改变契约，qa 可统一调整 |

## 八、`gates.md` 视觉段的写法

> 本节只写**产物格式**；`gates.md` 的写入纪律、行生命周期、经验标记两列仍以 `templates/gates.md` 头部为准。

### 8.1 段落位置

`### 2.4 V 段 — 视觉与设计系统`

尺子 = `design.md` + 本文件。段落位置在 `gates.md` §二「验收追溯矩阵」下、`2.3 B 段` 之后。

### 8.2 行号与列

| 项 | 规则 |
| :--- | :--- |
| **行号** | `V<页章号>.<组码>`。页章号取 `ux.md` 的页章号（第一个页面章为 `2`）；**`0` 表示全站级检查** |
| **组码** | 两位数字，见 §三 9 组总表；⛔ 不用 G / S 前缀 |
| **屏宽与亮暗** | 写在**证据列**，⛔ 不进行号 |
| **一行是什么** | 一个页面 × 一个组。同一组可同时有全站行（页章号 0）与页行 |
| **分母** | 本轮**应出的 V 行数**：01 只出全站一行 `V0.01`、02 只出全站一行 `V0.02`、03~08 每页每适用组一行、09 每页一行 + 全站性能一行 `V0.09`；不适用组不出行；VS 不进分母 |

> 规则号（如 `VH-06.01`）与 V 行号（如 `V2.06`）是两套编号：前者是规则，后者是「页面 × 组」。规则号只在 §四 定义一次；行号只在 `gates.md` 出现。
> **视觉地基轮次没有业务页面**：03~08 与 09 的页面行落在页章号 `0`（组件陈列页），即 `V0.03`~`V0.09`；业务页面轮次按业务页章号出 03~08 行，09 另加全站性能行 `V0.09`。

**表头**：

| V 编号 | 组 | Verdict | 轮次 | 证据（端 · 视口 · 亮暗 · 截图 / 测试） | 实测结果（规则号 + 实测 / 允许） | 连续/回归 | 根因类别 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

### 8.3 判词聚合

```
  该组任一 VH FAIL ──► 该行 ❌ FAIL ──► 进 §三 Critical Failures，回 dev
  只有 VM 命中     ──► 该行 ✅ PASS（备注次要 N 条）──► 进 §四 Minor Failures
  只有 VS          ──► 不进本表 ──► 进合集板，不阻断、不进分母
  组不适用         ──► 不出行；在 §六 覆盖率备注写「组不适用」
```

- **连续/回归**、**根因类别** 两列沿用 `gates.md` §二 既有定义；视觉行的根因仍从六类中选（实现缺陷 / 设计遗漏 / 测试自身错 / 环境 / 第三方 / 规格歧义）。
- **FAIL 证据必含**：规则号 + 实测值 / 允许值 + 截图路径或测试文件与用例名。
- **覆盖率**：`gates.md` §六 覆盖率表新增一行「视觉 `V`」，分母 = 本轮应出的 V 行数（口径见 §8.2），未测项逐条列原因。
- **就地更新**：第 N 轮只改结果变了的行，⛔ 不新开「第 N 轮视觉」章节、⛔ 不整份重写。
- **页章号只追加**：新页面追加在页章末尾，⛔ 不在中间插入（前插会让 V 与 U 的编号整体漂移）。

### 8.4 合集板

| 项 | 规则 |
| :--- | :--- |
| 是什么 | qa 产出的 VS 汇总板：一条 VS 一行，配截图 / 录屏与一句观察 |
| 放哪 | `.cc_code/docs/qa/`（与逐轮报告同目录） |
| 谁看 | 主人；qa 只整理证据，不下审美结论 |
| 卡不卡流程 | **不卡**。合集板不进 PASS / FAIL、不进分母、不触发回环 |
| 与 V 段关系 | 互补：V 段管可机检的硬阈值，合集板管只能人看的格调问题 |

## 十二、证据格式

### 12.1 机器判词（VH / VM）

```
<规则号> | <页名 / 区域> | <端> @ <视口> <亮|暗> | 实测 <数值> | 允许 <值 / 集合成员> | <检测方式> | 证据 <截图路径 或 测试文件::用例 或 axe 节点 或 Lighthouse 报告>
```

例（占位，不是真实项目数据）：

```
VH-06.01 | 定价页 / 三列卡片 | web @ 1440 亮 | 实测 顶部差 3px | 允许 ≤1px | 运行时样式与几何 | 证据 .cc_code/test/visual/align.spec::pricing-cards-top
```

### 12.2 人判（VS）

```
<VS 号> | <页名> @ <视口> <亮|暗> | 截图 <路径> | 观察 <一句话，只描述看到什么>
```

- VS 只写观察，不写「好 / 坏 / 高级 / 廉价」这类裁决词。
- 合集板一条 VS 一行，可附多张截图（亮 / 暗、390 / 1440）。

### 12.3 测试位置写法

- 测试 = `测试文件路径::用例名`。
- 截图 = 相对仓库根的路径（放 `.cc_code/docs/qa/` 或 `project.md` §六 登记的临时目录）。
- axe = 规则 id + DOM 节点定位。
- 性能 = Lighthouse 报告路径 + 三项指标实测值。

## 十三、禁止事项

1. ⛔ **qa 不得自定审美**：VS 只给证据，不写「好看 / 不好看」的判词，不用个人偏好替代 `design.md`。
2. ⛔ **不得把视觉模型意见当判词**：任何图像理解模型的输出只能进 VS 线索与合集板，不得写 VH / VM、不得阻断。
3. ⛔ **不得改基线迁就实现**：失败轮禁冻结；范围外差异只能判回归，不能「顺手更新基线」。
4. ⛔ **不得改阈值 / 跳检查**：`design.md`、`project.md` §六、本文件的阈值都不能为实现让路；axe serious / critical 不得跳过。
5. ⛔ **dev 不得手改生成的主题文件**，不得在主题入口之外写色值，不得修改 `.cc_code/test/visual/` 与基线。
6. ⛔ **uiux 不得放水**：锁定前自检未过全组，不得交主人看；不得在 `ux.md` 写色值 / 字体 / 圆角 / 阴影（换肤判据在 `design.md`）。
7. ⛔ **architect 不得读 `design.md`**，不得把审美值写进技术契约。
8. ⛔ **不得混家族**：一个项目只用一个组件库家族；片段只按 `frontend-forms.md` 的五步与兼容表使用。
9. ⛔ **不得在中间插入页章**：新页面只追加；前插会让 V 与 U 编号整体漂移。
10. ⛔ **不得把 VS 塞进分母**：合集板不卡流程、不进 PASS / FAIL、不触发回环。
