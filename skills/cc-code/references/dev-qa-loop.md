# 开发 → 测试循环协议（执行器共用，单一出处）

> **受众**：`agent-mvp` / `agent-feature` / `agent-uiux` / `agent-debug` 的主控（编排者，不扮演任何角色）。四个执行命令正文只放指针，⛔ 不复述本文件。
> **一句话**：qa 判、dev 改，按失败项各自计轮，最多 3 轮；仍不过就出升级包交人，禁止无限循环。
> **只管单线循环**：泳道内的栅栏、越界退回、汇合回归以 `parallel-lanes.md` 为准；本文件不重复其规则。

## 一、谁写判词（只有 qa）

| 角色 | 能做什么 | 不能做什么 |
| :--- | :--- | :--- |
| 主控 | 原样转交 FAIL 清单、按轮次派 dev 与 qa、每轮后做一次校准 | 改判词、合并判词、补判、替 qa 写 `gates.md` |
| qa | **唯一判词作者**：出 Verdict + 逐项 FAIL 清单 + 证据 | 改需求、改契约、改方案 |
| dev | 修复 + 自检 + 完成报告 | 自证通过（自检 pass 只是自检，不是判词） |

- 判词的唯一落点是 `gates.md`（qa 唯一写者，主控不代写）；bug 链另在 `bugs.md` 上写状态与卡点。
- 期望只来自 `prd.md` / `ux.md` / `api.md` / `data.md` 与设计规格，⛔ 不拿代码或 dev 的解释当尺子。
- subagent 不能问用户：dev / qa 要问人的事，写进报告的「冲突上报」或卡点，由主控交人。

## 二、一轮的定义

```
 qa 跑本段范围（不抽样）
   │
   ├─ 全绿 ─────────────────────────────► 本段 PASS（进结算；结算规则见各执行命令正文）
   └─ 有失败 ↓
        ① qa 出逐项 FAIL 清单（每项带证据）        ← 这一份就是本轮判词
        ② 主控原样喂回 dev（不改写、不减项、不去编号）
        ③ dev 只修：不改需求、不改契约、不改方案
              └─ bug 链：不改 B-n 方案，状态保持「待修复」不动
        ④ dev 修完 → 重算回归范围（§四）→ 自检
        ⑤ 主控调 qa 复测：本轮 FAIL 项 + 回归范围
        ⑥ 主控做一次校准（静默），回到顶部
```

每一轮的计数单位是**一个失败项**，不是「一轮里失败了几条」，也不是页面数或 agent 人数。一轮 = 「qa 出清单 → dev 修 → qa 复测」的完整来回；缺任一环节都不算一轮（qa 没复测就没走完，dev 没拿到原样清单就没开始）。

## 三、按失败项计数

| 规则 | 说明 |
| :--- | :--- |
| 轮次按失败项各自计 | 不按页面、不按本轮总失败数、不按 agent 计 |
| 新失败项从第 1 轮起算 | 后一轮才首次出现的失败项，自己从 1 起，不继承其它项的轮次 |
| 已复测通过的项 | 出循环，不再计轮；只有被后续改动的回归范围覆盖到时才重跑 |
| 撞上需求 / 契约冲突 | 不算失败项、不计轮：dev 停下交人，回环不处理需求与契约问题 |
| 同一项连续 3 轮仍不过 | 只这一项升级交人（§五），同轮其它项照常走完 |

## 四、修完的回归范围

dev 每轮修完，交给 qa 复测的范围按下面取并集、去重：

1. **本轮回喂的 FAIL 项**：原样断言 / 原样判定项，必须逐项复测；
2. **本轮 dev 改动源文件的影响面**：用 `project.md` §六 登记的代码索引工具重算（`affected` 空结果按各执行命令的处置自查：测试被忽略、纯 HTTP 型无 import 边、命名需过滤）；
3. **非常规命名测试**：按 `project.md` §六 登记的 glob 补跑；
4. bug 链另加 B-n 用例本身（回归测试必须落盘且通过，硬条件见 `agent-debug` 正文）。

**拿不到影响面时的兜底**（保持各命令现有语义，不统一改写）：

| 执行命令 | 兜底 |
| :--- | :--- |
| `agent-mvp` / `agent-feature` | 退回「同模块已 PASS 项」 |
| `agent-debug` | 退回全量 |
| 索引工具未装 | 静默用全量，不报（⛔ 健康时不提索引） |

## 五、3 轮仍不过的升级包

```
 某失败项第 3 轮复测仍不过
   ├─ qa 判词落盘：用业务语言写清卡点
   │     ├─ 验收链 → 写进 gates.md（失败项 + 三轮证据）
   │     └─ bug 链 → B-n 状态写回「待裁决」，卡点写进「待裁决」字段
   ├─ 主控停本段：不结算、不硬修、不回规划链、不点名去找谁
   └─ 主控原样转述主人（转述去编号，规则 = Agent.md §四第 6 条）
```

升级包必须带齐（qa 给、主控转述）：

| 项 | 内容 |
| :--- | :--- |
| 失败项 | 编号 + 一句话现象（业务语言） |
| 三轮账 | 每轮改了什么、哪项变了、哪项没变 |
| 证据 | 截图 / 日志 / 测试名，位置按 `project.md` §六 登记；线上现状只留路径与结论 |
| 已排除 | 明确试过无效的方向 |
| 要主人定什么 | 一句问句，能给默认建议就给 |

**禁止**：把第 4 轮当第 1 轮重开；换个人 / 换个 agent 重试同一项；主控自己改需求或契约绕过；改判词或删失败项凑绿。

## 六、任务单最小字段

派 dev / qa 的任务单必带（泳道模式下另加 `parallel-lanes.md` §四「派 Dev」的四项：泳道模式、覆盖断言、只准写、自检范围）：

| 字段 | 内容 |
| :--- | :--- |
| 角色与范围 | 派 dev 还是 qa；本段只读哪些文档小节、只写哪些文件（读写权限唯一出处 = `Agent.md` §三） |
| 做 | 一句话职责：dev 修哪几项 / qa 验哪几项 |
| 判据 | 期望出处：`prd.md` §1.5 断言、`ux.md` 判定项、`api.md` / `data.md` 契约；视觉项按 `ui-gates.md` |
| 命令 | 一律取自 `project.md` §六，⛔ 任务单里不硬编码测试 / 构建 / 自检命令 |
| 输出 | 完成报告（文件清单 + 自检 pass/fail + 「采纳经验」一行）+ 回归范围 |
| 轮次 | 本项现在第几轮、上轮改了什么 |

> 任务单只写「验什么、修什么、写哪里」，⛔ 不写实现方案（那是角色自己的判断）与需求内容（需求在原文件里，让 agent 自己去读）。

## 七、与并行泳道协议的分工

| 事项 | 唯一出处 |
| :--- | :--- |
| 一轮怎么算、按项计轮、≤3 轮、升级包、任务单字段、单线回归范围 | 本文件 |
| 泳道怎么拆、启用体检、栅栏一 / 栅栏二、越界退回、汇合回归、浏览器单实例 | `parallel-lanes.md` |
| 泳道内的轮次 | 仍按本文件「按失败项各自计」；泳道退回只影响被判失败的那条 |

> 冲突时：泳道机制以 `parallel-lanes.md` 为准，单线循环以本文件为准。两处都只写规则，不写具体命令。

## 八、不适用清单

| 场景 | 处理 |
| :--- | :--- |
| `just-do-it` | ⛔ 不适用本协议；它自带 ≤2 轮回环（规则在 `skills/just-do-it/SKILL.md`） |
| 规划命令（`plan-mvp` / `plan-feature` / `plan-debug` / `plan-uiux`） | ⛔ 不适用——规划命令不写码、不出判词 |
| `agent-whole-qa` | ⛔ 不适用单段回环；它按「全轮总失败数」收敛（规则在 `skills/agent-whole-qa`） |
| `deploy` 冒烟 | 不是回环；证据落产物目录后直接报结果 |
| 泳道内 | 适用，但栅栏与退回以 `parallel-lanes.md` 为准（分工见上文 §七） |

## 九、指针

- 断言的最小必测集：`assertions.md`（本目录，全部 qa 命令共用）。
- 视觉规则与编号（VH / VM / VS）、三个检查时机、允许值集合、基线纪律：`ui-gates.md`（规则唯一出处，本文件不复述）。
- 前端形态、三旋钮、组件库家族：`frontend-forms.md`。
- 结算（`milestone-log.md` / `status.md` / 后台派 `curator`）：各执行命令正文；本文件只管循环本身，⛔ 不写结算规则。
