# 并行泳道协议（执行器共用，单一出处）

> **受众**：`agent-mvp` / `agent-feature` / `agent-uiux` / `agent-whole-qa` 的主控（编排者，不扮演任何角色）。四个执行器正文只放指针，⛔ 不复述本文件。
> **一句话**：卡片串行，卡内泳道并行。agent 顺序（dev → qa）、派活顺序、唯一写者全部不变；变的只是「同一个 agent 同时派几个人」。
> **泳道从哪来**：只来自生成项目 `active/project.md` §九（architect 规划时写）。执行器只读，⛔ 绝不自己拆、绝不现场补泳道。

## 一、纯净性对照（并行后哪些不变）

| 铁律 | 并行后 | 靠什么守住 |
| :--- | :--- | :--- |
| agent 串行 dev → qa | 不变 | 栅栏同步：两道栅栏之间同时在跑的全是同一种 agent，dev 与 qa 从不同时开工 |
| 执行器不规划 | 不变 | 泳道只读 §九；不合规就退回单线程，⛔ 不替规划补洞 |
| 唯一写者 | 不变 | 并发期间子 agent 只回报告；`gates.md` / `bugs.md` 由 qa 写（单个、串行落盘），`status.md` / `milestone-log.md` 由主控写（归属见 `Agent.md` §二） |
| 派活串行（一次一张卡） | 不变 | 并行只发生在一个阶段 / 一个增量内部 |
| QA 不拿代码当尺子 | 不变 | qa 读写权限照旧，只是断言范围缩到本泳道 |

## 二、启用体检（每个阶段 / 增量开工前，主控静默做）

```
 读 project.md §九「泳道」表中本阶段（或本 F 号）的行
      ├─ 没有行 / 只有一条泳道 ──────────────► 单线程跑，开工前报一行「本阶段单线程（无泳道）」
      └─ 有两条以上 ↓
 逐项体检：
   ① 各泳道「只准写」两两不重叠（拿不准算重叠）
   ② 依赖只指向「地基」或同阶段泳道，且不成环
   ③ 本阶段要做的断言，每条恰好归一条泳道
      ├─ 任一不过 → 报一行「泳道表不合规（哪一项），本阶段单线程跑」
      │             ⛔ 不修表 —— 修表是 plan-mvp / plan-feature 的事
      └─ 全过 ↓
 按依赖分层：地基 → 只依赖地基的泳道 → 依赖上一层的泳道 …
 每层同时开工数 ≤ §九「并发上限」（缺省 3），超出的同层排队
```

> agent-feature 的「本阶段要做的断言」= 增量定位算出的差集；已 PASS 的断言所在泳道整条跳过。

## 三、生命周期

```
 体检通过
    ▼
 地基泳道（单线程：Dev → QA，与今天一致）
    ▼
 ┌─ Dev 甲 ─┬─ Dev 乙 ─┬─ Dev 丙 ─┐   同一层同时开工
 └──────── 栅栏一：全部写完 ────────┘
    ▼
 主控核对改动归属 + 全局检查（见第四节）
    ├─ 有泳道越界 / 全局检查挂在某泳道 → 只退回该泳道 Dev，再过栅栏一
    └─ 全过 ↓
 ┌─ QA 甲 ─┬─ QA 乙 ─┬─ QA 丙 ─┐    同时验，只回报告不写文件
 └──────── 栅栏二：全部验完 ────────┘
    ▼
 主控派一个 qa（单个）把各份报告原样落进 gates.md（主控不代写）
    ├─ 有泳道没通过 → 只把没通过的泳道退回 Dev（各自计轮，≤3）
    │                 退回的几条之间照样走两道栅栏
    │                 某条 3 轮仍不过 → 只这一条出升级包进交人报告，其余泳道照常结算
    └─ 本层全过 → 下一层泳道（回到 Dev 并发）
    ▼
 全部层通过 → 汇合回归（见第五节）
    ▼
 阶段结算（有泳道升级未解 → 只这几条进交人报告，其余照常结算；报告格式见 dev-qa-loop.md §九）
```

**校准**：`/cc-code:cc-code` 只在两道栅栏处由主控做一次，⛔ 不为每条泳道各做一次。

## 四、派活与栅栏一核对

**派 Dev（单条消息里发多个 Agent 调用）**，每份任务单必带：

| 项 | 内容 |
| :--- | :--- |
| 泳道模式 | 明写「泳道模式」+ 泳道名 |
| 覆盖断言 | 本泳道断言号（原文由 dev 自己去 prd / ux / api 读） |
| 只准写 | §九 原样抄给它 |
| 自检范围 | 只跑本泳道的测试；全局类型检查 / 代码规范留给主控 |

**栅栏一核对（主控）**：

```
 各泳道完成报告里的文件清单  vs  工作区实际改动
   ├─ 报告里的文件落在自己「只准写」之外 → 该泳道越界，退回撤回越界改动
   ├─ 工作区有改动但没有任何泳道认领   → 无主改动，停跑出交人报告（⛔ 不猜归属、⛔ 不中途问）
   └─ 全部对上 ↓
 代码索引有积压 → 静默同步一次
 全局检查（类型 / 代码规范 / 构建；命令来自 project.md 测试基建契约，没有就挂起这一步进交人报告）
   ├─ 报错文件落在某泳道「只准写」内 → 退回该泳道
   ├─ 报错文件属于地基               → 停跑出交人报告（地基已验过，又坏了说明规划漏了共享文件）
   └─ 全过 → 进栅栏二
```

## 五、QA 与回归

| 环节 | 跑什么 | 谁写结果 |
| :--- | :--- | :--- |
| 泳道 QA | 本泳道断言的逻辑层 + 接口层 + **只读视觉检查**（截图 / 机检，不写库、不独占端口，可在各自标签页做）；回归面 = 本泳道改动文件算出的影响面 | 并发期间 qa 只回报告；栅栏二后由一个 qa 落盘 |
| 汇合回归 | 全部泳道改动合并后的影响面 + 本阶段端到端主链路；**改数据的浏览器测试与全部视觉基线对比只在这里跑** | 单个 qa，直接写 gates.md |

> **只读视觉检查可以在泳道内并行**：截图与机检不碰数据、不独占端口，各 qa 在自己的标签页做即可。
> **改数据的浏览器测试仍只在汇合回归**：它要独占端口和测试库，并发跑互相污染，结果不可信。
> **测试运行器（Playwright 测试）自起的临时无头浏览器不计入 §九 的单实例**；共享单实例协议只管人工 / 探索取证那一个浏览器。

**汇合回归没通过**：

```
 没通过的断言能归到某条泳道 → 退回该泳道 Dev（计入它的轮次）
 归不到任何泳道（跨泳道集成问题）→ 派单个 dev 修，修复面 = 这些失败项
                                     同样 ≤3 轮，仍不过 → 出升级包进交人报告
```

## 六、主控写回纪律

- 各泳道 qa 报告的判词由**一个** qa **原样**落进 `gates.md`，一份写完再写下一份，⛔ 不改判、不合并、不补判；主控不代写 `gates.md`。
- `status.md` 的坐标 / 卡点、`backup/milestone-log.md` 的里程碑，只在阶段结算时由主控写一次。
- 给 dev 的回喂可以带编号；转述给用户时按 `Agent.md` §四第 6 条去编号。

## 七、全量清算的修复轮（agent-whole-qa ❹）

```
 本轮全部没通过项，按 qa 报告里的「涉及文件」分组：
   两组涉及的文件有交集 → 合成一组（直到组与组之间文件两两不交）
 每组派一个 dev，同时修（≤ 并发上限）
 修完 → 栅栏一核对：
        两组的完成报告改到了同一个文件 → 撞车，这两组合并，派单个 dev 重修
        有改动没有任何组认领              → 无主改动，停跑出交人报告
      → 回归门照旧（失败项 + 全部组改动合并后的影响面）
 收敛门控照旧：按「全轮总失败数」判，不按组判
```

## 八、不适用

| 场景 | 为什么不并行 |
| :--- | :--- |
| `agent-debug` | 一个 bug 一条线，拆开反而丢根因上下文 |
| `just-do-it` | 小改动，开泳道的成本比改动本身大 |
| §九 没写泳道的老项目 | 自动单线程，零影响 |

## 九、浏览器单实例复用（所有执行器通用）

> **一句话**：全流程只起一个浏览器实例，所有 qa 共用；**第一个用浏览器的 qa 负责打开，收口 qa 负责关闭**。
> 本协议只管**实例数与复用**，不改变各执行器的浏览器测试范围和数据隔离要求。
> ⚠️ 主控的 `allowed-tools` 不含浏览器工具，**不要**把开 / 关交给主控。

```
主控 PREFLIGHT
  └─ 只检查：可用浏览器工具恰好一套 → 记下逻辑名        ← 不操作浏览器
        ▼
清点 qa（owner）
  ├─ 实例不存在 → 建立唯一实例
  └─ 实例已存在 → 直接复用
        ▼
qa 甲 / qa 乙 / qa 丙（照常并发，各自做浏览器验收）
  ├─ 建自己的 tab，记住句柄
  ├─ 每次浏览器工具调用前切回自己的 tab
  └─ 收工只关自己的 tab
        ▼
收口 qa（closer）──► 关掉残留 tab + 关闭实例一次
```

| 角色 | 允许 | 禁止 |
| :--- | :--- | :--- |
| 主控 | 检查唯一性、把逻辑名传给执行器 | 打开 / 关闭浏览器（无工具权限） |
| owner（首个用浏览器的 qa） | 建立唯一实例、复用已有实例 | 中途关闭实例 |
| 其他 qa | 建 / 切 / 关自己的 tab | 新开实例、关闭整个浏览器 |
| 收口 qa（closer） | 关残留 tab、关闭实例一次 | 借收口测试或改文件 |
| dev | 不碰浏览器 | — |

**七条硬规则**：

1. **工具唯一出处** = `project.md §六`「界面驱动工具」（按端登记：网页类 Playwright、小程序 wechat-devtools）；网页端的逻辑名缺省 `playwright`，实际调用以宿主可用工具名为准。⛔ 同一项目不混用两套浏览器 MCP。
2. **同一会话只允许一个浏览器实例**；owner 建立或复用，closer 关闭一次。
3. **每个 qa 自建 tab**，并在**每次浏览器工具调用前切回自己的 tab** —— 并发兄弟 agent 会改掉「当前页」。
4. **收工只关自己的 tab**；⛔ 非 closer 不关闭整个浏览器。
5. **实例失联**（被关 / 崩溃）→ 写进 `escalate` 上报主控，⛔ 不自行重建第二个实例。
6. **产物显式落盘**到 `project.md §六`「浏览器产物目录」，不依赖 MCP 默认输出目录。
7. **测试运行器自起的临时浏览器不计入单实例**：视觉机器检查写成 Playwright 测试后，运行器自己起的无头浏览器由运行器管生命周期（用完即关），不算本协议的「第二个实例」，也⛔ 不交给 owner / closer 管理。

> 并发 qa 同时操作同一份应用数据时，防串数据由 `project.md §六`「QA 数据隔离」负责（独立库 / 独立账号 / seed 前缀）；本协议只解决浏览器实例数。
