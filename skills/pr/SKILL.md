# /cc-code:pr — 交付编排器（一个命令，点一下就交）

> **定位**：开发侧最后一棒。把**已验收通过**的改动按规范交给外部审查平台：commit → 推送功能分支 → 带描述建合并请求，然后停手。
> **格式来源**：commit 与合并请求描述的格式只在 `references/mr-template.md`；仓库自带合并请求模板（`.gitlab/merge_request_templates/Default.md`）时以仓库为准。本文件只讲编排，⛔ 不复述格式。
> **内外边界**：平台怎么分档、怎么审、怎么合并，与本命令无关。被平台打回或线上出 bug，照常走 `plan-debug` / `plan-feature`，本命令不处理回流。

| 用法 | 场景 |
| --- | --- |
| `/cc-code:pr` | 交付本次增量；类型（功能 / 修复 / 文档）自动判断 |

> 点击即授权：本命令内的开分支、提交、推送、建合并请求不再逐条确认；⛔ 不碰主干、不强推、不合并。

## 前置检查（任一不过即停，告诉主人缺什么、该走哪个命令）

| 检查 | 不过时 |
| --- | --- |
| 有 `.cc_code/active/` | 指路 `/cc-code:init` |
| 有可提交的改动（未提交改动，或当前分支有未推送的提交） | 告诉主人「没有可交付的改动」 |
| 有远端仓库 | 告诉主人先配置远端 |
| 改动里没有密钥与环境文件 | 列出文件，停；⛔ 不替主人删、不读值 |
| 功能 / 修复：本次增量全部验收通过（`gates.md` §一 Verdict = PASS 且 §三 为空） | 指路对应的 `agent-*` 命令 |
| 文档：改动只有文档 | 不需要验收 |

> 密钥检查只看两样：文件名（`.env` 系列、私钥、证书、凭据文件）与改动正文里真实凭据形态的长串；命中即停。

## 运行逻辑

```
 ① 前置检查
     ▼
 ② 判类型
     改动只有文档 ─────────────► 文档（跳到 ⑤）
     本次验收的是 bug 修复 ────► 修复
     其余 ─────────────────────► 功能
     ▼
 ③ 派 qa 交回「提交证据」：qa 重跑本次断言的命令，写证据文件
     （怎么测的 · 出事怎么撤 · 关联规格 · 影响面），交回路径
     重跑 FAIL ──► 停，指路对应的 agent-* 命令
     ▼
 ④ 要不要决策日志：改动碰到仓库审查规则文件里的「高风险区域」
     ├─ 碰到 ──► 派 architect（只读）交回决策日志三段；交不出的项一次只问主人一项
     └─ 没碰到 / 仓库没有清单 ──► 不带（档位由平台判，判高会打回补齐）
     ▼
 ⑤ 按 references/mr-template.md 拼 commit 与描述
     描述 = 改了什么 + 证据文件原文 + 决策日志（证据文件整段拼入，主控不改一字）
     缺项取不到 ──► 一次只问主人一项；仍没有 ──► 停，列缺口
     ▼
 ⑥ 在主干上 ──► 先开功能分支；已在功能分支 ──► 沿用
     ▼
 ⑦ 提交 ──► 推送功能分支
     ▼
 ⑧ 建合并请求（见下表）；该分支已有合并请求 ──► 只推送，不重建
     ▼
 ⑨ status.md 坐标写「已交平台」+ milestone-log 一行 ──► 报告合并请求链接 ──► 停手
```

### ③ 取证（agent: qa）

| 项 | 内容 |
| --- | --- |
| 任务单 | 只写「本次增量范围 + 交回提交证据」；⛔ 不夹带主控的理解 |
| 交回 | 证据文件路径（`.cc_code/docs/qa/` 下；做法只在 `agents/qa.md`「提交证据」一节） |
| 证据规则 | 命令、输出、截图都是 qa 实测原文；⛔ 主控不总结、不润色、不补写「测试通过」 |
| 入库 | 证据文件随本次 commit 一起提交，平台与日后复盘都能查 |

### ④ 决策日志（agent: architect，只读）

| 项 | 内容 |
| --- | --- |
| 判据 | 「高风险区域」清单只在业务仓库的审查规则文件里（暂名 `review.md`），本命令只读，⛔ 不抄副本 |
| 交回 | 为什么这样做 · 考虑过、放弃了什么 · 风险与兜底 |
| 边界 | architect 只读、不落盘；交不出的项交回主控，由主控一次一项问主人 |

### ⑥ 分支命名

| 类型 | 分支 |
| --- | --- |
| 功能 | `feature/<功能短名>` |
| 修复 | `fix/<问题短名>` |
| 文档 | `docs/<主题短名>` |

短名用英文小写加连字符；目标分支 = 远端默认分支。

### ⑧ 建合并请求

| 环境 | 方式 |
| --- | --- |
| GitLab，有 `glab` 且已登录（`glab auth status`） | `glab mr create`：标题 = commit 标题，描述走标准输入，截图逐张作附件上传，`--yes` 跳过交互 |
| GitLab，没有 `glab` | 推送时用 GitLab 推送选项建合并请求（建、目标分支、标题、描述；描述里换行写 `\n`）；截图无法上传 → 报告里列出截图路径，请主人拖进合并请求 |
| GitHub | `gh pr create`，参数同上 |
| 都不可用 | 已推送即止；报告里给出完整描述原文，请主人手动建 |

> 命令以官方为准：执行前查该工具最新官方文档（有 Context7 用 Context7），冲突以官方为准。

## ⛔ 铁律（本命令唯一规则源）

| 铁律 | 违反时 |
| --- | --- |
| 未验收不交付 | 前置检查不过就停（文档类除外） |
| 证据只取原文 | 命令与原始输出只取 qa 交回的原文；⛔ 写「测试通过」类自述、⛔ 拿总结冒充输出 |
| 不判档位 | 档位只由平台判；本命令只决定带不带决策日志 |
| 不碰主干 | 只推功能分支；⛔ 强推、⛔ 合并、⛔ 改主干 |
| 密钥不进 | 前置检查拦截；⛔ 读值、⛔ 打印 |
| 格式不抄 | 格式唯一出处 = `references/mr-template.md`（仓库自带模板优先） |
| 提交后停手 | ⛔ 轮询平台；打回与线上 bug 由主人照常走 `plan-debug` / `plan-feature` |

## 谁写什么

| 动作 / 文件 | 写者 |
| :--- | :--- |
| 开分支、提交、推送、建合并请求 | 主控（`active/Agent.md` §一 唯一显式例外，仅限本命令） |
| 提交证据（命令 / 原始输出 / 截图 / 影响面 / 关联规格） | `qa`（主控只搬运） |
| 决策日志三段 | `architect` 只读交回（主控只搬运） |
| `status.md` 坐标、milestone 一行 | 主控 |

> 其余（本命令不碰的 prd / ux / design / project / data / api / gates / bugs / 业务代码）见 `active/Agent.md` §一 / §三；角色权限的单一出处 = Agent.md §三，主控是编排者，不扮演任何角色。
