## 二、 核心编程原则 (cc-code Philosophy)
所有提交的代码，必须经受以下原则的拷问：

1.  **KISS** — 拒绝炫技，可读性大于极致抽象。函数尽量 < 50 行。
2.  **YAGNI** — 仅实现当前明确所需功能，抵制过度设计，不预留「未来可能用到」的接口。
3.  **DRY** — 出现三次的重复代码必须抽离为 Hook / Utils。
4.  **SOLID 强制落地：**
    *   **SRP** 组件只负责渲染，逻辑抽到 Custom Hook。
    *   **OCP** 多用 children 扩展，少用 boolean props 堆叠。
    *   **DIP** 高层模块不直接调用底层 API，中间必须有 Service 层。
5.  **⛔ 零硬编码（铁律）** — 业务代码只引用，⛔ 禁止出现值的字面量。新出现的值先按下表定去处：

    | 值的类型 | 去处 | 例子 |
    | :--- | :--- | :--- |
    | 随环境变化、可调的值 | `config.json` | API 地址、端口、超时、重试次数、分页大小、功能开关、限流阈值 |
    | 敏感值 | `.env` | 密钥、token、数据库密码、第三方 secret |
    | 业务上固定的值 | `constants` 常量文件 | 状态枚举、角色名、错误码、路由路径、存储 key、事件名、队列名、缓存 key 前缀、定时任务名、正则、MIME 类型 |

    | 豁免（不算硬编码） | 原因 |
    | :--- | :--- |
    | `0` / `1` / `-1` / 空串 / `true` / `false` 这类语义自明的值 | 抽成常量反而难读（KISS） |
    | 测试夹具里的数据 | 测试数据本来就要写死 |
    | `config.json`、`constants`、`.env` 本身 | 它们就是定义值的地方 |

    | 文件 | 入 git | 作用 |
    | :--- | :--- | :--- |
    | `.env` | ⛔ 不入（写进 `.gitignore`） | 存真实敏感值 |
    | `.env.example` | ✅ 入 | 只列 key 不写值，一看就知道要配哪些变量 |

    > `config.json` 用 JSON 格式（TS / Python 等均可直接读）；三个文件的具体路径见第三节。

### ⛔ 三条铁律（违反即 `affected` 永久失效）

```
① 测试代码必须入 git
   codegraph 尊重 .gitignore → 被 ignore 的测试不进索引
   → affected 查不到 → 精准回归退化为全量瞎跑
   ✅ 该 ignore 的是「测试产物」: coverage/ test-results/ *.png
   ⛔ 绝不能 ignore 的是「测试代码」: *.spec.ts *.test.ts

② 测试必须 import 被测源码
   affected 沿 import 依赖图反向回溯算影响面
   静态 import ✅  动态 await import() ✅  纯 HTTP 打接口 ⛔（无边可追）
   → HTTP 型测试在本表「说明」列标注「affected 不覆盖」

③ 非标准命名必须在本表登记 glob
   affected 默认只认 *.spec.* / *.test.* / __tests__/
   smoke-f5.ts 这类需显式 --filter，glob 不登记 = 无人知道怎么调
```

### 7.2 统一字段（JSONL，一行一条）

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `ts` / `level` / `msg` / `service` / `category` | ✅ | `msg` 一句话，不拼接变量；`category` 为模块层级，如 `app.order.pay` |
| `requestId` | ✅（请求内） | 关联主键，跨服务一致 |
| `route` / `method` / `status` / `durationMs` / `outcome` | 宽事件必填 | `route` 写路由模板，不写原始 URL；`outcome` = success / error / denied |
| `err` | ERROR 必填 | name / message / stack（框架错误另带 digest） |
| `userId` | 可选 | 只记 ID |
| `ctx` | 可选 | 业务字段一律收进此命名空间，⛔ 不平铺到顶层 |

### 7.3 什么入日志

| 类别 | 记什么 | 级别 |
| :--- | :--- | :--- |
| 请求进出 | 每个请求结束时 **1 条宽事件**（成功失败都必出） | INFO |
| 错误异常 | 错误名、信息、堆栈、所在路由 | ERROR |
| 外部调用 | 对象、耗时、成败（DB / 第三方 API / 队列）——并入宽事件 | 失败时另记 WARN |
| 状态变更 | 关键数据从 A 变成 B（订单、支付、权限） | INFO |
| 关键分支决策 | 走了哪个分支、原因（鉴权拒绝、限流、降级） | INFO / WARN |
| 细节排查 | 中间变量、循环过程 | DEBUG（默认关） |
| ⛔ 不记 | token、密码、cookie、完整请求体 / 响应体、手机号与邮箱原文 | — |

### 7.4 输出（同一门面，按环境换出口）

| 项 | 开发 | 测试 | 生产 |
| :--- | :--- | :--- | :--- |
| 默认级别 | DEBUG（可调） | INFO | INFO |
| 终端 | 一行摘要；ERROR / WARN 高亮 | — | — |
| 存储 | `.logs/` JSONL，按大小滚动，保留最近 N 个 | `.logs/` 每轮一个文件 | stdout JSON → Vercel Logs / CF Workers Logs |
| 清理 | 滚动自动删最旧 | 按轮次 | 平台保留期自动过期 |
| 查询 | 按 `requestId` / `level` / `route` 过滤 | 同左 | 平台面板按字段筛 |

| 配置项 | 去处（遵循第二节零硬编码） | 本项目值 |
| :--- | :--- | :--- |
| 日志级别 | `.env`（`LOG_LEVEL`） | [待填写] |
| 本地目录 / 单文件大小 / 保留个数 N | `config.json` | [待填写] |

### ⛔ 三条铁律（违反即 Critical）

```
① 业务代码禁止直接打印（console.log / print / fmt.Println），必须走日志门面
② 每个请求都有 requestId：入口沿用可信上游值或新生成，并写回响应头 x-request-id
③ 7.3「⛔ 不记」的内容一律不准出现；脱敏用写死的白名单，⛔ 禁止由用户输入决定脱敏路径
```

### ⛔ 四条铁律

```
① 同一阶段内，各泳道「只准写」两两不重叠
   几条泳道都要改的文件（路由注册、表结构迁移、依赖清单、
   全局样式、共享类型、多语言词条）一律划进「地基」泳道，排最前
② 泳道只许依赖「地基」或同阶段已完成的泳道，⛔ 禁互相依赖成环
③ 每条断言只归一条泳道；一条断言拆不开 = 这两条泳道该合并
④ 拆不出两条以上互不相干的泳道就不拆 —— 单线程本身就是合法答案
```
