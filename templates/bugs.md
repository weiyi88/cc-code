# 🐛 未修复 bug 工作上下文 (bugs.md)

> **施工便签** · 写者与流程见 `Agent.md` §三 qa 卡片（本文件不复述）。`/cc-code:plan-debug` 自动整理（复现成功即写，不等批准），`/cc-code:agent-debug` 只接 状态 = 待修复 的条目，修复通过后条目原文搬进 `backup/retired/bugs.md`。
> **本文件只装「正在处理的 bug 的工作上下文」**：现象 / 复现 / 期望出处 / 日志证据 / 需加探针 / 根因 / 爆炸半径 / 方案（修法）。其中 现象 / 根因 / 爆炸半径 / 方案（修法）/ 状态 与 `plan-debug` 的四段告知一一对应——四段告知本体不落盘，只有结论落进这些字段。
> ⛔ 不装：验收结果（→ `gates.md`）、需求与交互断言（→ `prd.md` / `ux.md`）、视觉数值与规则（→ `design.md` / 插件 `ui-gates.md`，本文件只引用编号）、已修复的 bug（→ `backup/retired/bugs.md`）。

### 写入纪律

| 纪律 | 说明 |
| :-- | :--- |
| **常态为空** | 只存未修复的 bug（带状态，见下表）；修复 PASS 后原文整段搬 `backup/retired/bugs.md` 再从本文件移除（结算见 agent-debug）。⛔ 不直接删 |
| **qa 是唯一写者** | 所有字段与状态都由 qa 改；dev 只读诊断、主控只传话（权限出处 = `Agent.md` §三） |
| **B 序列独立** | B-1, B-2, … 独立递增，⛔ **绝不复用 A / U / V 序列**（A、U、V 永久稳定，bug 断言生命周期是天级） |
| **期望必须有出处** | 主人原话，或既有 A / U / V 断言号，或 `design.md` 的设计数值，或 `ui-gates` 的视觉规则号，或已冻结截图基线，或允许值集合；⛔ 禁止从代码现状反推期望 |
| **集合内差异不算 bug** | 实测值落在允许值集合内（`design.md` 数值 ∪ 陈列页快照 ∪ token 透明度变体），或在 `design.md` 附录 B 已登记的例外范围内 → **不是 bug**，⛔ 不登记 B-n；允许值集合与例外的唯一口径 = `ui-gates` §五 / §九 |
| **单条 ≤20 行** | 只装结论（根因/爆炸半径/方案各一两句）；侦察过程与四段告知本体不落盘 |
| **就地更新** | 诊断每推进一步，在同一条 B-n 上改字段、改状态；⛔ 不为同一个 bug 另起新条目 |
| **过期搬走不删** | 修复完的条目、主人判定「不是 bug」的条目，原文进 `backup/retired/bugs.md`（一字不丢）；语义追溯 = `milestone-log` 一行 + 留守的回归测试。⛔ 本文件内不留已结案条目 |

### 状态（每条 B-n 必有「状态」字段，只有这三种）

| 状态 | 含义 | 谁改成它（均由 qa 写） | 之后去哪 |
| :-- | :--- | :--- | :--- |
| `待诊断` | 已复现、已登记现象与期望出处，根因 / 爆炸半径 / 方案尚空 | qa：复现成功当场；或裁决后重新复现成功且还没诊断过 | 主控派 dev 只读诊断，诊断报告原样转 qa |
| `待裁决` | 卡在需要主人回答的一个问题上，「待裁决」字段里有那句业务语言问题 | qa：①根因是契约错 ②根因是需求错 ③找不到期望出处 ④复现不了；或修复 3 轮仍没过（卡点写在「待裁决」字段） | 主人回答后，由主控按 `plan-debug` 铁律 2 派 architect / pm，或续接 qa 重新复现；qa 更新 B-n，删「待裁决」行 |
| `待修复` | 根因 / 爆炸半径 / 方案已齐，契约和需求都没问题（或已改好），可以动手修 | qa：收到 dev 诊断且判为纯实现层；或裁决完成后 | `/cc-code:agent-debug` 只接这个状态；修复期间状态不变，复测 PASS 后条目原文搬 retired |

> `agent-debug` 派 dev 修之前不改状态（qa 此时尚未派出）。主人裁决「不是 bug」：条目原文搬 retired 后移除，没有「已关闭」状态。

## 未修复清单

> **条目模板（全站唯一定义；`plan-debug` 与 `agent-debug` 都引用本模板，字段集以此为准）**，按此追加：
>
> ```markdown
> ## B-1｜<模块-功能简述> | 状态：待诊断
> *   **现象：** <主人看到的错误表现，一两句>
> *   **复现：** <步骤；复现不了写「未复现」+ 已试步骤>
> *   **期望出处：** <A12.4 / U2.1 / VH-06.01 / `design.md` §三 字号阶梯 / 已冻结基线 / 允许值集合 / 主人原话；找不到写「未找到」>
> *   **日志证据：** <requestId + 日志位置 + 关键字段；无则写「无」/「无基建」>
> *   **需加探针：** <位置 + 要观察的值；证据足够写「无」>
> *   **根因：** <一句话因果，取自 dev 诊断报告；待诊断时写「待诊断」>
> *   **爆炸半径：** <业务语言：影响哪些功能 / 页面 + 修完要回归哪些测试（测试面由 qa 用 affected 补）；估算则注明；待诊断时写「待诊断」>
> *       技术备注：<影响文件清单（dev 给；供 dev / qa 用，一行）>
> *   **方案：** <修法，一句话，取自 dev 诊断报告；业务层说法，注明是否动契约 / 需求（动则不是纯实现层，走裁决）；待诊断时写「待诊断」>
> *   **待裁决：** <仅 状态=待裁决 时有；一句业务语言问题，或 3 轮修复仍未过的卡点；裁决后删除此行>
> ```
