# 🎨 设计规格 (design.md)

> **生成项目的落点**：`.cc_code/active/design.md`（初始化时由本模板拷入，之后由 uiux 就地维护）。
> **L2 表现层（视觉半边）** · 唯一写者 **uiux agent** · 读者 **dev（据此生成主题、实现页面）与 qa（据此判视觉）**。
> 🚫 **pm 禁读**（L1 意图层不得被 L2 反推）；🚫 **architect 不读**（技术契约只取布局与家族，不取视觉数值）。
> 📐 **写什么**：全项目唯一视觉事实源 —— 色彩、字体与排版、间距与栅格、形状与深度、动效、图标与图像、组件长相、各端主题映射、页面构图。
> 🚫 **不写什么**：页面结构与交互五态 / testid（→ `ux.md`）、业务规则（→ `prd.md`）、组件库家族与版本 / 技术选型（→ `project.md` §一.1）、实测结果（→ `gates.md`）。
> ⚖️ **判据一句话**：换一套皮肤仍然成立 → 写 `ux.md`；换皮肤就会变 → 写这里。
> 🧭 **规则唯一出处** = 插件 `skills/cc-code/references/ui-gates.md`（判词、规则号、阈值）；**形态与选型规则** = 插件 `skills/cc-code/references/frontend-forms.md`。本文件只记「本项目是什么」。

### ⛔ 写入纪律（active = 最新 + 最完整 + 最纯净）

| 纪律 | 说明 |
| :--- | :--- |
| **就地收敛** | 视觉变更**只改对应小节里变化的那几行**（新增项插进它该在的表格），⛔ 禁新开 `## 增量 F-n` 章节、⛔ 禁整份重写。同一个数值在本文件永远只有一处描述 |
| **全项目一份** | 各端差异只写 §九「各端主题映射」，⛔ 不按端拆第二份设计规格 |
| **状态行唯一** | §0 状态行只取四个值（草稿 / 已锁定 / 改版待实现 / 不适用（无前端））；锁定时写日期，改版时写本次范围。状态没变就 ⛔ 不动这一行 |
| **锁定后只经 plan-uiux 改** | 状态为「已锁定」后，只有 `/cc-code:plan-uiux`（模式二 改版）能改本文件，其他命令 ⛔ 不改。新页只用已锁数值 / 已锁组件 / 已知构图时可免门但要登记进本次改动范围，引入新数值 / 新组件 / 新视觉母题的必须回 `plan-uiux`（两档规则唯一出处 = `plan-feature` 命令正文） |
| **生成物不手改** | dev 生成的主题文件是生成物，⛔ 禁止手改；要改数值 → 改本文件 → 重新生成主题 |
| **过程外置** | 讨论过程 / 方向卡取舍 / 轮次记录 ⛔ 不落盘（留痕 = `backup/change-log.md` 一行）；本文件只留「视觉现在是什么」 |
| **台账外置** | 每次改版在 `backup/change-log.md` 追加**一行**（格式见 `Agent.md` 归档规范）；本文件内不留台账 / 历史痕迹 |
| **过期搬走不删** | 作废的数值 / 组件 / 构图：原文整段 append 到 `backup/retired/design.md`（带日期 + 来源小节 + 退役原因），再从本文件移除。⛔ 不留删除线尸体、⛔ 不直接删内容 |

| 项 | 值 |
| :--- | :--- |
| **状态** | 草稿（新建默认；其余取值：已锁定 / 改版待实现 / 不适用（无前端）） |

| **本次改版范围** | —（「改版待实现」时填受影响页面与改动面） |

### 0.1 状态含义

| 取值 | 含义 | 谁能推进 |
| :--- | :--- | :--- |
| **草稿** | uiux 正在写，或尚未过视觉门「定了」 | uiux；dev ⛔ 不开工页面 |
| **已锁定** | 主人已在 `plan-uiux` 说「定了」，日期已落 | dev 可据此生成主题、实现页面；qa 据此判视觉 |
| **改版待实现** | 模式二已「定了」，等 `agent-uiux` 落地 | agent-uiux |
| **不适用（无前端）** | 项目没有前端 | 全链路放行，qa 视觉段标「不适用」 |

```
草稿 ──主人「定了」──► 已锁定 ──plan-uiux 模式二「定了」──► 改版待实现
                              ▲                                      │
                              └────────── agent-uiux 落地完成 ───────┘
```

### 0.2 与项目坐标的对应（两处各管一件事，⛔ 不互相抄）

| 本文件 §0 | `status.md` 的「风格：」行 |
| :--- | :--- |
| 草稿 | 未锁（老项目首次运行可为「未锁（冷启动豁免）」，只用一次） |
| 已锁定 | 已锁 |
| 改版待实现 | 已定未实现 |
| 不适用（无前端） | 无前端 |

> §0 是本文件自身状态的唯一处（uiux 写）；项目坐标行由主控写 `status.md`，uiux ⛔ 不写 `status.md`。
> 「改版待实现」= 本次改版的新数值已获批准、代码尚未落地。落地完成、qa 冻结新基线后：`status.md` 由主控改为「已锁」；本行由 uiux 在下一次出场落盘时就地改为「已锁定」并更新锁定日期（⛔ 不改其他行）。补写之前，执行器以 `status.md` 的「已锁」为准。
