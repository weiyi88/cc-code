# 📋 项目逻辑 (prd.md)

> **L1 意图层** · 唯一写者 **pm agent** · 全系统唯一「应然」真相源。
> ⛔ **禁止从代码反推**：本文件定义「应该是什么」，代码定义「现在是什么」。若从代码反推需求，QA 将退化为「拿代码验代码」，验收环节彻底失效。
> 🚫 **pm 禁读 `ux.md` 与 `design.md`**：L1 不得被 L2 反推；页面、原型与视觉归 uiux。
> 📐 **写什么**：需求摘要（端与形态结论、推荐栈与家族）、分模块的业务逻辑、规则、边界、验收断言。
> 🚫 **不写什么**：页面结构与交互（→ `ux.md`）、视觉数值与组件长相（→ `design.md`）、组件库家族与主题入口（→ `project.md` §一.1）、字段与表结构（→ `data.md`）、接口参数（→ `api.md`）、架构选型（→ `project.md`）、实测结果（→ `gates.md`）。

**判据三句**（三条互斥，按顺序判）：

```
能脱离界面存在的规则      ──► 写这里（prd.md）
离开界面成立不了、换皮肤仍成立 ──► 写 ux.md（结构 / 交互 / 布局）
换一套皮肤就会变          ──► 写 design.md（视觉数值 / 组件长相）
```

### ⛔ 写入纪律（active = 最新 + 最完整 + 最纯净）

| 纪律 | 说明 |
| :--- | :--- |
| **就地收敛** | 增量变更**直接改写对应模块小节的那几行**，⛔ 禁新开 `## 增量 F-n` 章节、⛔ 禁整份重写。同一条规则在本文件永远只有一处描述 |
| **新增就位** | 端与形态结论、推荐栈与家族**就地改写 §〇 对应表**；新模块 / 新规则 / 新断言插进它该在的小节（新断言续编进 §1.5 主表），⛔ 不堆文件末尾 |
| **断言归主表** | 新断言一律**续编进 §1.5 验收断言主表**，⛔ 禁在增量小节另起断言表 —— 业务断言只有一张主表，散了 QA 就拿不全（视觉与交互各有其主表：`ux.md` 各页『交互五态矩阵』与 `design.md`） |
| **过程外置** | 需求清单 / 冲突收敛表 / 裁决过程 / 待澄清 ⛔ 不落盘（对话内裁决即用即弃，留痕 = `backup/change-log.md` 一行）；本文件只留「现在的规则是什么」 |
| **台账外置** | 每次增量在 `backup/change-log.md` 追加**一行**（F 号 / 日期 / 层 / 文件 / 模块 / 改了什么 / 裁决 / 详情，格式见 `Agent.md` 归档规范）；本文件内不留任何台账/附录/历史痕迹 |
| **过期搬走不删** | 作废的规则 / 作废的断言：原文整段 append 到 `backup/retired/prd.md`（带日期 + 来源小节 + 退役原因），再从本文件移除。⛔ 不留删除线尸体、⛔ 不直接删内容 |
