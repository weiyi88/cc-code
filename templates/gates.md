# 🛡️ QA 实测结果 (gates.md)

> **L4 验收层** · 由 [QA] 角色维护 · **Dev 禁读**（防被既定答案带偏）。
> ⚠️ **本文件只装「实测结果」，不装「验收标准」。** 标准在 `prd.md` 的 §1.5 验收断言。
> 混装是历史上最常见的失效原因：标准与结果一旦同文件，改结果就等于改标准。

```
prd.md §1.5 验收断言  ──尺子(应然)──►  QA 实测  ──结果(实然)──►  gates.md
ux.md  §2.3 U 编号五态 ──┘                                          │
                                                    FAIL 清单 ──► 原样喂回 Dev
```

### ⛔ 写入纪律（active = 最新 + 最完整 + 最纯净）

| 纪律 | 说明 |
| :--- | :--- |
| **就地更新** | 第 N 轮验收**只改 §二 矩阵里结果变了的那几行**（Verdict / 测试位置 / 实测结果）。⛔ **禁新开「第 N 轮」章节**、⛔ 禁整份重写 —— 追加式写法会让本文件随轮次线性膨胀，且「某条断言现在什么状态」要跨 N 轮 grep 才知道；整份重写则把没变的行白烧一遍 |
| **行数恒定** | 矩阵行数 = 分母（`A` 条数 + `U` 条数），不随轮次增长 |
| **详情外置** | 逐轮完整报告 → `docs/qa/<YYYY-MM-DD>-round-N.md`；本文件只留「当前状态」 |
| **过期搬走不删** | §三/§四/§五 只留**未修复**项；修好的、断言已作废的、已结算的 B-n 行：原文整段 append 到 `backup/retired/gates.md`（带日期 + 来源小节 + 退役原因），再从本文件移除。⛔ 不留尸体、⛔ 不直接删内容 |

> 📢 **输出可读铁律**：本文件的编号只给 agent 查；向用户汇报时不出现编号，规则见 `Agent.md` §四第 6 条。

## 二、验收追溯矩阵

> ⭐ **全量溯源**：每一条 `A` 断言、每一条 `U` 判定项都必须在此有一行，一条不漏。
> 编号直接引用 `prd.md` / `ux.md`，**禁止另起一套编号**。
> 复测时**改这一行**，不新开轮次章节。

### 2.2 U 段 — UI 布局 / 交互五态（尺子：`ux.md` §2.3）

> 态：i 正常 / l 加载 / s 完成 / e 错误 / m 空。`ux.md` 标 `N/A` 的态不计入分母，但要在此留行注明。

| U 编号 | Verdict | 轮次 | 证据（截图 / 用例） | 实测结果 |
| :--- | :--- | :--- | :--- | :--- |
| U2.1.i | ✅ PASS / ❌ FAIL / ⚠️ UNVERIFIABLE | [n] | `[待填写]` | [待填写] |

### 2.3 B 段 — bug 修复（尺子：`bugs.md` 的 B-n 条目「期望出处」）

> 仅记录**期望出处为主人原话**（无既有 A/U 断言对应）的 B-n 结果；期望出处为既有 A/U 断言的 bug **就地改写 2.1 / 2.2 对应行**，不在此开行。
> 行生命周期：修复 PASS 且回归测试留守后，此行**整行搬进 `backup/retired/gates.md`** 并从本表移除（追溯靠 retired 原文 + 留守的回归测试 + `backup/milestone-log.md` 一行）；`bugs.md` 条目同时删除。本表常态只剩**未修复**的 B-n。

| B 编号 | Verdict | 日期 | 回归测试位置 | 实测结果 |
| :--- | :--- | :--- | :--- | :--- |
| B-1 | ✅ PASS / ❌ FAIL | [日期] | `[测试文件 + 用例名]` | [待填写] |

*   ✅ **PASS** — 有测试覆盖且实测通过（须 cite 测试文件 + 用例名 + 运行结果）
*   ❌ **FAIL** — 测试失败或无覆盖（须精确说明缺什么 / 怎么挂的）
*   ⚠️ **UNVERIFIABLE** — 无法判定（须说明还需要什么证据）

> ⛔ 永不把 FAIL 四舍五入成「大概没问题」，永不进位。

| 范围来源 | 范围大小 | 备注 |
