# 🛡️ QA 实测结果 (gates.md)

> **L4 验收层** · 由 qa agent 维护 · **Dev 禁读**（防被既定答案带偏）。
> ⚠️ **本文件只装「实测结果」，不装「验收标准」。** 尺子来源固定四处：
> - `prd.md` §1.5 验收断言 → **A 段**
> - `ux.md` 各页『交互五态矩阵』（页章号 `.3`）+『可交互元素清单』（页章号 `.4`） → **U 段**
> - `.cc_code/active/design.md` + 插件 `skills/cc-code/references/ui-gates.md` → **V 段**（规则号、阈值的唯一出处）
> - `bugs.md` 条目的「期望出处」 → **B 段**
> 混装是历史上最常见的失效原因：标准与结果一旦同文件，改结果就等于改标准。

```
  尺子来源（应然）
  ├─ prd.md §1.5 验收断言（A）
  ├─ ux.md 各页交互五态矩阵（U）
  ├─ design.md + ui-gates 视觉规则（V）
  └─ bugs.md B-n 期望出处
          │
          ▼
    QA 实测 ──► 结果（实然）──► gates.md
                    │
                    └──► FAIL 清单 ──► 原样喂回 Dev
```

### ⛔ 写入纪律（active = 最新 + 最完整 + 最纯净）

| 纪律 | 说明 |
| :--- | :--- |
| **就地更新** | 第 N 轮验收**只改 §二 矩阵里结果变了的那几行**（Verdict / 测试位置 / 实测结果）。⛔ **禁新开「第 N 轮」章节**、⛔ 禁整份重写 —— 追加式写法会让本文件随轮次线性膨胀，且「某条断言现在什么状态」要跨 N 轮 grep 才知道；整份重写则把没变的行白烧一遍 |
| **行数恒定** | 矩阵行数 = 分母（`A` 条数 + `U` 条数 + `V` 行数），不随轮次增长。**V 行 = 一个页面（或全站）× 一个适用规则组**；屏宽与亮暗写**证据列**，⛔ 不进编号、不另开行；经验标记是行内两列，不另开行 |
| **视觉判词只按规则** | V 段判词来自 `ui-gates` 的机检结果；视觉模型只给证据进合集板，⛔ 不当判词、不阻断。⛔ 不改阈值、不改基线迁就实现（纪律唯一出处 = `ui-gates` §七 / §十三） |
| **详情外置** | 逐轮完整报告 → `docs/qa/<YYYY-MM-DD>-round-N.md`；视觉合集板 → `docs/qa/`（不卡流程）；本文件只留「当前状态」 |
| **过期搬走不删** | §三/§四/§五 只留**未修复**项；修好的、断言已作废的、已结算的 B-n 行：原文整段 append 到 `backup/retired/gates.md`（带日期 + 来源小节 + 退役原因），再从本文件移除。⛔ 不留尸体、⛔ 不直接删内容 |

> 📢 **输出可读铁律**：本文件的编号只给 agent 查；向用户汇报时不出现编号，规则见 `Agent.md` §四第 6 条。

### 经验标记两列（每张矩阵表最后两列，列数与列序固定，行数不变）

> 给 curator 整理经验用的**唯一依据**：QA 在同一断言行标，编号永久稳定，curator 靠「行编号 + 标记 + 轮次」避免重复处理。标记只描述「这一行连续或回头失败了，根因属于哪一类」，不写经验本身。

| 列 | 取值 | 怎么填 |
| :--- | :--- | :--- |
| **连续/回归** | `连续(R<n>)` 上一轮 ❌ FAIL、本轮又 ❌ FAIL；`回归(R<n>)` 上一轮 ✅ PASS、本轮 ❌ FAIL；`—` 其余情况（首次 FAIL、PASS、UNVERIFIABLE） | 只在本轮该行判 ❌ FAIL 时判定并写；`R<n>` = 本轮轮次。行后来转 ✅ PASS **不清除**标记（留给 curator 整理），之后再次 FAIL 才用新标记覆盖 |
| **根因类别** | 实现缺陷 ／ 设计遗漏 ／ 测试自身错 ／ 环境 ／ 第三方 ／ 规格歧义（六选一） | 取证后按下表判定，只写类别；一时判不出就留空，下一轮补 |

| 根因类别 | 含义 |
| :--- | :--- |
| 实现缺陷 | 规格明确，代码没按规格做 |
| 设计遗漏 | 规格 / 契约没覆盖到这种情形，代码按设计做也会错 |
| 测试自身错 | 测试写错了，代码没问题 |
| 环境 | 本地 / 数据 / 依赖环境导致的失败 |
| 第三方 | 外部服务或第三方库的行为导致 |
| 规格歧义 | 需求本身有歧义，要主人裁决 |

> 报告里同步列出本次带标记的行（B-n 行在搬进 `backup/retired/gates.md` 之前也要列），供主控原样转交 curator；QA 只标记，不整理经验，也不读任何经验库。

### 2.4 V 段 — 视觉与设计系统（尺子：`.cc_code/active/design.md` + 插件 `skills/cc-code/references/ui-gates.md`）

> ⭐ **本段是视觉层（第四层）的唯一落点。** 规则号（`VH` / `VM` / `VS`）、组码、阈值、允许值集合、基线纪律的唯一出处 = `ui-gates`，⛔ 本文件不复述规则内容，只装判词与证据。
> **一行 = 一个页面（或全站）× 一个适用规则组**；屏宽与亮暗写在**证据列**，⛔ 不进编号。规则号（如 `VH-06.01`）与 V 行号（如 `V2.06`）是两套编号：规则号只在 `ui-gates` 定义，行号只在本文件出现。
> **页章号**取 `ux.md` 的页面章号（第一个页面章为 `2`）；**`0` = 全站级**。视觉地基轮次没有业务页面，页面行全部落在 `0`（组件陈列页），即 `V0.03`~`V0.09`；业务页面轮次按业务页章号出 03~09 行（09 = 响应式 / 可访问性 / 基线），另加全站性能行 `V0.09`。**时机决定出哪几行**：`V0.01`（设计数值）只在本轮时机含「锁定前」时出一行，开发后 / 全量 / 部署轮次 ⛔ 不查；`V0.02`（依赖与源码）每轮全站一行；不适用组不出行。新页只追加，⛔ 不在中间插页。
> **组不适用**不出行，在 §六 覆盖率备注写「组不适用」。**VS（人判）不进本表**，只进合集板（`docs/qa/`），不阻断、不进分母、不触发回环。
> **判词聚合**：该组任一 `VH` FAIL → 本行 ❌ FAIL → 进 §三；只有 `VM` 命中 → 本行 ✅ PASS（备注次要 N 条）→ 同步 §四；`UNVERIFIABLE` 只在证据不足（无基线 / 非 100% 缩放 / 锚点未登记）时用，不算 PASS、不进分母。
